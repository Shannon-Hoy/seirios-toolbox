1. The files: setup, moving, updating

Every tool is one self contained HTML file. There is nothing to install, and no file you load ever leaves your machine: rasters, boundaries, and coordinate files are read and processed inside the browser tab. Fonts and, in the Endurance Planner, optional live map layers load from the internet when it is available; everything else works without it. The hub page (index.html) links the tools by filename, so the whole set lives in one folder:

  1. index.html, the hub page
  2. nodata-fixer.html
  3. raster-masker.html
  4. raster-coverage-polygon.html
  5. coordinate-converter.html
  6. instructions.html, this page

Moving or sharing the toolbox. Copy the folder. That is the entire procedure: USB drive, network share, another laptop, a zip in an email. Double click index.html on the destination machine and everything works. Any modern browser opens the tools; they are tested in Chrome.

Updating a tool. Replace its file, keeping the exact filename. Two Windows habits cause most update problems: File Explorer hides extensions by default, so raster-masker.html may display as tools_Raster_Masker, and a re-downloaded file often arrives as tools_Raster_Masker (1).html, which the hub will not find. Rename to the exact original before replacing.

After replacing a file, the browser may keep showing the old version from its cache. Press Ctrl+F5 on the tool's tab, or close the tab and reopen the file. If a change you expected is missing, this is the first thing to check.

Adding a tool. Drop the new file in the folder and add an entry to the list at the top of the hub page's source, which is commented to show the format.

Desktop shortcut

Two ways, both using the toolbox icon file Seirios_Toolbox.ico kept in the same folder.

  1. Through Chrome: open index.html, then Chrome menu, Save and Share, Create shortcut. Chrome places a shortcut on the desktop using the page's own icon.
  2. Through Windows: right click the desktop, New, Shortcut, browse to index.html, finish. Then right click the shortcut, Properties, Change Icon, browse to Seirios_Toolbox.ico.

2. NoData Fixer

Purpose. Some sources write empty cells as 0 instead of a proper NoData flag. Multibeam mosaics pulled with Extract Grid in the NCEI Bathymetry Viewer are the common case; the result renders as a flat sea level plane in Fledermaus. This tool rewrites those cells with a real NoData value and exports the repaired grid.

Steps

  1. Drop in the GeoTIFF. The info card shows dimensions, coordinate system, and any NoData flag found in the file.
  2. Pick the rule for which cells become NoData (options below).
  3. Set the NODATA value to write. 0 matches the Fledermaus SOP; -9999 is the common GIS convention. Both work in Fledermaus.
  4. Optionally pick an output coordinate system. Keep source is the default and the right choice for deliverables.
  5. Convert, read the sanity check panel, then download the Arc ASCII, the fixed GeoTIFF, or both. Both hold the identical repaired grid.

Options

Treat exactly 0 as NoData. The default, matching the NCEI and SOP case. Recommended for deep water grids.
Only cells flagged NoData inside the tiff. Use when the grid legitimately contains 0 m values, such as intertidal data, and the file's own flag is trustworthy.
Everything at or above a threshold. For example -0.5 flags anything shallower than 0.5 m depth, catching gap cells that came through as tiny near zero values.
Output coordinate system. Keep source, WGS 84, Web Mercator, UTM at the grid center, or any EPSG code, with a zone to code lookup. Reprojection resamples by nearest neighbor and squares the cells so the Arc ASCII stays legal. Prefer the source CRS for survey deliverables.

Outputs. Filenames come from the input with _NoDataFixed at the end, and the EPSG code before it when reprojected. Values pass through unchanged, so vertical units are whatever the source used, meters for NCEI and GEBCO products.

3. Raster Masker

Purpose. Keep only the cells of a data grid that pass rules built on one or more mask grids. The driving case: GEBCO bathymetry masked to measured only cells using the TID grid, with an optional depth cut.

Steps

  1. Drop in the rasters: GeoTIFF, NetCDF straight from the GEBCO download app, or Esri ASCII. Note .asc carries no coordinate system, so its coordinates are assumed to match the other rasters.
  2. Assign roles: the grid to be cut is Data, the grids that decide what survives are Mask. A raster can hold both roles at once, which is how you filter by the data grid's own values.
  3. Build a rule on each mask. Integer grids like TID get value presets; numeric grids get comparisons.
  4. With several masks, choose whether a cell must pass every mask (AND) or any mask (OR).
  5. Apply, inspect the preview, then export.

Options

Depth filter button. Once a numeric grid is assigned as Data, one click adds it as its own mask preset to drop land. The tool checks the sign convention first: grids with real negative values get keep below 0, positive down depth grids get keep above 0, and the message says which it chose and why.
TID presets. Measured values 10 to 17, or custom value lists and ranges like 10-17, 42.
Flip switches. Each mask can be inverted on its own, and the combined selection can be flipped at the end, for example to keep only the altimetry predicted areas instead of the measured ones.
Cross CRS masks. Masks in a different coordinate system than the data grid are aligned automatically.
Output reprojection. Same selector and EPSG lookup as the other tools.

Outputs. GeoTIFF, Arc ASCII, XYZ, NetCDF, and a rendered image GeoTIFF for float grids.

4. Raster Coverage Polygon

Purpose. Convert rasters into coverage footprint polygons with a statistics report. This replaces the Global Mapper create area from equal values step and does not produce the sliver swarm of raster to polygon in ArcGIS Pro.

Steps

  1. Drop in the raster: GeoTIFF of any data type including RGBA image exports, Esri ASCII, NetCDF, or an XYZ point file, which is binned to a grid at a suggested cell size you can change.
  2. Check the advice line. The tool samples the file and switches its own NoData rule when the declared flag is a lie, which NCEI mosaics are known for.
  3. Optionally load a clip boundary (see below).
  4. Set gap closing, minimum polygon and hole sizes, and simplification as needed.
  5. Run, read the result panel and preview, then download.

Options

Data rules. Alpha transparency for image exports, the file's NoData flag, a specific value such as 0, or a value range.
Built in World EEZ. One click loads Marine Regions World EEZ v12 (low resolution) from the pack file that ships beside the tool, with every zone named, a search box, and a high seas preset that selects everything and keeps the outside. Attribution: Flanders Marine Institute (2023), marineregions.org, doi:10.14284/632, CC BY 4.0. The boundaries are generalized for planning, not for legal, economic, or navigational use.
Coverage by region and the report. Clipping to several features adds a per region table, mapped area and share for each zone, carried into the CSV, and an Export report button produces a print ready document with the results, the region table, and the attribution.
Clip boundary. GeoJSON, KML, or a shapefile. For a shapefile pick the .shp and .dbf together, or one after the other; the .dbf carries the feature names. A selection panel opens with a checkbox list and a clickable map: features touching the raster are preselected, click a polygon to toggle it. Overlapping features union rather than cancel.
High seas and inversions. The keep the outside switch inverts the clip: select every EEZ and keep the high seas.
Detail. Auto decimates very large grids for speed; full resolution traces the exact cell outline when your machine has the memory.
Output reprojection. Any EPSG code with the zone lookup. Statistics are geodesic on the WGS84 ellipsoid whenever the source CRS is known, and match ArcGIS Pro with Calculate Geometry set to geodesic regardless of the output CRS.

Outputs. Shapefile zip with area, perimeter, and hole attributes, GeoJSON, KML, WKT, and a statistics CSV. The CSV carries the full accounting, including cell counts and boundary coverage figures.

When a boundary extends beyond the raster, coverage figures describe the part of the boundary this raster sees, not the whole feature. The methods note and the CSV both say so. To report coverage of an entire EEZ, run each tile and combine the cell counts, or use a mosaic that spans it.

5. Coordinate Converter and UTM Zone Finder

Purpose. Convert positions between decimal degrees, degrees minutes, degrees minutes seconds, and UTM, one at a time or in batch, with the matching EPSG code on every UTM result.

Steps

  1. Quick convert: type or paste a position in any format. Every format comes back with a copy button and a precision note stating what the written digits can actually resolve.
  2. The map: click to find the UTM zone anywhere, or to tell the tool where easting and northing files belong. Norway and Svalbard grid zone exceptions are noted where they apply.
  3. Batch: paste lines or drop a file (.csv, .txt, .xyz and similar). Each line is detected on its own, names are kept, and results export as CSV or GeoJSON points.
  4. Table parser: drop a column file, confirm the guessed role above each column, and convert. Built for the files batch mode cannot read: spreadsheet exports with headers, quoted fields, coordinates split across degree, minute, and second columns, hemisphere letters in their own column, or UTM easting and northing columns.

Table parser options

Column roles. The tool detects the delimiter, quoted fields, and header row, then guesses each column: name, latitude, longitude, the six split coordinate columns, hemisphere letters, easting, northing, zone, or keep as is. Check the dropdowns over the preview before converting; the guesses are good but they are guesses, and two unlabeled decimal columns can be ambiguous.
Passthrough columns. Anything marked keep as is, depth, notes, times, rides through unchanged into every export. Rows without a readable position are skipped and counted, never silently dropped.
UTM columns without a zone. If the file has easting and northing but no zone column, a zone and hemisphere selector appears; a zone column in the file, including forms like 55N, wins over the selector.
Outputs. CSV, GeoJSON points with the passthrough columns as properties, KML placemarks, and Copy table for Excel or Word, which puts a formatted table on the clipboard that pastes with borders and headers. Checkboxes add degrees minutes, degrees minutes seconds, and UTM with the EPSG code as extra columns.
Precision notes. Amber warnings appear when a requested output format is coarser than the input, so copied coordinates never silently pretend to more accuracy than the source had.

6. Checking outputs

These tools were built with AI and validated against pyproj, GeographicLib, numpy, and shapely during development, but validation covers the paths that were tested, not every file the wild produces. Spot check anything that matters: open a shapefile in ArcGIS Pro or QGIS and compare an area with Calculate Geometry set to geodesic, re-run one conversion through PROJ, count cells in Python. The tools state their methods in the interface, geodesic versus planar, cell resolution basis, resampling method, so the comparison is always defined. If a number cannot be checked, treat it as unverified.
